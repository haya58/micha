

## 追加で実装したいこと
- 検索で時間がかかっているときにユーザに一次応答を返す → OK
- ユーザについて記憶をした際に「〇〇さんについて新しいことを覚えました！」と embed 応答を返す → OK（記憶保存成功時に緑embedで通知）
- メンションをつけなくても反応するモード切替機能を追加 → OK（`RESPOND_ALL=true` で対象チャンネルの全発言に応答。実行時コマンド切替は未対応）
- Bot のログイン時に「Botがログインしました」とEmbedで投稿するようにしてほしい → OK（起動時に1回のみ投稿。`LOGIN_NOTICE_CHANNEL_ID`未設定時は対象カテゴリの先頭チャンネル）
- Bot がエラーになった場合、通常の応答と区別するために明確なエラーメッセージを Embed で投稿するようにしてほしい → OK（応答生成失敗時は赤色embedで通知、通常発言は送らない）
- Twiiterリンク内の画像を取得できる仕組みがあるか？（これは優先度低。実装が複雑になるようであればユーザに確認する） → OK（fxtwitter公開API経由で本文＋画像を取得。動画は対象外）
- Botが投稿できるカテゴリとは別に、Botが読み取りだけできるチャンネルを複数指摘できるようにしてほしい。 → OK（`READONLY_CHANNEL_IDS`＋`READONLY_POLL_SEC`。定期取得して応答文脈に反映。投稿・返信はしない）
  - つまり、指定したチャンネルに関してはBotはただ読み取る（定期的な実行でよい）。その内容をBotのランダム発言やユーザがBotとやり取りするチャンネルに反映したい
- コードベースの変更とは別に簡潔に外部仕様・内部仕様をまとめたドキュメントを docs/ 以下に作成してほしい → OK（`docs/spec-external.md`・`docs/spec-internal.md`）
- README.md を現状に合わせて更新して。手元での起動方法、Docker Composeでの起動方法、k8s環境へのデプロイ方法をまとめて → OK
- 設定ファイルを  .env で管理するのは結構複雑になってきている。toml での管理に切り替えたい。 → OK（TOML単独方式。環境変数参照を廃止し `deploy/` にデプロイ資材を集約）
- 絵文字でのインタラクション機能をつけたい。絵文字のエイリアスから内容を推定して、ユーザのメッセージに対してリアクションをつける。
ただしつけすぎるとうざいので程々の頻度にしておく。

## 不具合？
